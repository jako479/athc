# generate-schedule CLI plan

**Goal:** `athc generate-schedule --season YEAR [--previous FILE]` builds a league's season schedule from the game's own league files, the previous season's `.lge` (saved after its last playoff game, for the standings; without `--previous`, the upcoming file) and the upcoming season's (for the conferences, divisions and team names; by default `<league>.lge` in the league's `path` folder), and writes a `.txt` and `.html` schedule plus an `.html` report to the current folder. It is the Commissioner's tool: hidden from the command list, documented in SCHEDULER-COMMANDS.txt, and no coach runs it. The command keeps its shape; this plan fits its help to cli-help.md, makes the two options take the `.lge` file itself and `--previous` optional, warns instead of failing on an unfinished season, adds the division finish to the overall order and breaks the last tie with a coin toss from the run's seed, bounds `--seed` and `--time-limit` so a bad value is a usage error instead of a solver failure, checks that the current folder takes a file before the long solve, and makes Ctrl+C stop the run the way it stops every other athc command.

**Status:** proposal, 2026-10-13; nothing changed yet. Every choice is decided below, with its reason next to it. Depends on cli-help.md landing first (its rule 25). Describes the code at main `dade898` (standings and structure from the league's `.lge` files). Reviewed in six rounds; the findings are folded in.

Reinstall athc.`. It never exits 1: it is not a checker.
- Ctrl+C: during a solve it kills the process. `make_solver` leaves CP-SAT's `catch_sigint_signal` at its default, true ("If set, catching the SIGINT signal will terminate the search gracefully, as if a time limit was reached", `sat_parameters.proto`), but that promise does not hold on Windows: OR-Tools' handler store is `thread_local static std::function<void()> handler_;` (`ortools/util/sigint.h`), filled by `Register` on the solving thread, while Windows runs a Ctrl+C handler on a thread of its own ("When a CTRL+C interrupt occurs, Win32 operating systems generate a new thread to specifically handle that interrupt", MS Learn `signal`), where that store is empty. A standalone probe (a Golomb-ruler CP-SAT model with a 20 s budget on one worker, `CTRL_C_EVENT` sent 4 s in, the venv's OR-Tools 9.15.6755) showed the first press ending the process at once: exit code 0xC0000409 (3221226505), no output, so in athc no `FAIL` line and no `exit` line in the run log. After a solve that was not interrupted, the C runtime's SIGINT handler is the default, not Python's (OR-Tools' destructor sets `signal(SIGINT, SIG_DFL)`, `sigint.cc`; read through `ucrtbase.signal`), so a Ctrl+C between the phases, while phase 2's model is built or while the three files are written also ends the process with Windows' own code and no athc line. Only a Ctrl+C before phase 1's solve reaches the one place as Click's `Abort`: `FAIL Interrupted.`, 130. No document says any of this.
- Docs: `docs/scheduler/README.md`, `docs/scheduler/ARCHITECTURE.md`, `config/release/docs/SCHEDULER-COMMANDS.txt` ("Commissioner only"; "intentionally left out of the general COMMANDS.txt"; "The previous season's <league>.lge (saved after its last playoff game) gives the standings"). `STATUS.md`'s scheduler section still says every run "writes to a new timestamped folder, so nothing is overwritten" (line 434); the code writes three files named to the minute in the current folder.

## 3. What other tools do

- **A required value is a named option, and two inputs with different parts are two named options.** clig.dev: "Prefer flags to args." "It's a bit more typing, but it makes it much clearer what is going on." Azure CLI's `az group create` lists `--location` and `--name` under "Required Parameters" and shows them in its usage without brackets. The two files here share one name, `<league>.lge`, so only the option names say which season is which. Click marks a required option `[required]` at the end of its help line (`core.py`, `get_help_record`) and refuses a run without it with `Missing option '--season'.` (`exceptions.py`, `MissingParameter`).
- **A configured default folder, an override, and `.` for the current folder.** cli-help.md rule 16 (from check-ppp-cli.md decision 3): no path means the configured default, `.` the current folder, an explicit path overrides both (check-ppp's precedents: pytest's `testpaths`, mypy's `files`, pyright's `include`, ruff's `[default: .]`). athc's `playpool check` takes no argument for the league's `play_path` or a folder instead.
- **A noted oddity that may be intended is a `WARN`.** architecture.md's message kinds: `WARN` is "noted, nothing failed", on stderr, never changing the exit code; `collect_files` gives `WARN <dir>: No .pln files.` for a folder with nothing to do and the run goes on.
- **The "League files folder is not set" line names the command's own way out.** cli-help.md rule 21: `FAIL <league.toml>: League files folder is not set. Run 'athc config set path FOLDER'`, then the command's own ending (` or pass --upcoming.` here); check-ppp-cli.md section 7 ends its path lines the same way (`Set ppp_path in <league.toml>, or pass the folder.`), so a first run shows the way out on the first line.
- **The seed is printed so a run can be repeated.** pytest-randomly: "The output will start with an extra line that tells you the random seed that is being used:" `Using --randomly-seed=1553614239`. athc's result line `Generated <n> games (seed <s>)` and the report's Seed row do the same.
- **The solver's own time units.** OR-Tools `sat_parameters.proto`, `max_deterministic_time`: "Maximum time allowed in deterministic time to solve a problem." "The deterministic time should be correlated with the real time used by the solver, the time unit being as close as possible to a second." It is a `double`, so any budget is taken and a larger one only lets the search run longer. `random_seed` is "optional int32 random_seed = 31 [default = 1];".
- **CP-SAT's own Ctrl+C does not work on Windows; a console handler that stops the search does.** `catch_sigint_signal`: "Indicates if the CP-SAT layer should catch Control-C (SIGINT) signals when calling solve. If set, catching the SIGINT signal will terminate the search gracefully, as if a time limit was reached." "optional bool catch_sigint_signal = 135 [default = true];" (`sat_parameters.proto`). `ortools/util/sigint.h`: "thread_local static std::function<void()> handler_;" and "static void SigHandler(int s);"; `sigint.cc`: `Register` ends with "signal(SIGINT, &SigHandler);", the handler is "void SigintHandler::SigHandler(int) { handler_(); }", the destructor "if (handler_ != nullptr) signal(SIGINT, SIG_DFL);". MS Learn `signal`: "SIGINT is not supported for any Win32 application. When a CTRL+C interrupt occurs, Win32 operating systems generate a new thread to specifically handle that interrupt." The probe (section 1): with the flag on, the first press ends the process at once, exit code 0xC0000409, no output; with the flag off, the press is deferred (Python's `signal` docs: "A long-running calculation implemented purely in C ... may run uninterrupted for an arbitrary amount of time, regardless of any signals received. The Python signal handlers will be called when the calculation finishes."): the solve ran to its 20 s budget and `KeyboardInterrupt` followed, and the C runtime's handler was still Python's afterwards; with the flag off and a console control handler installed through `ctypes` (`kernel32.SetConsoleCtrlHandler`) that calls `CpSolver.stop_search()` ("Stops the current search asynchronously.", `cp_model.py` lines 1781-1785) and returns true, the solve returned `FEASIBLE` at the press (3.6 s into a 20 s budget), the process went on, Python saw no `KeyboardInterrupt`, and its handler was intact. Click turns a `KeyboardInterrupt` out of a command into `Abort` whatever the mode (`core.py` lines 1456-1458), and the one place prints `FAIL Interrupted.` and exits 130 for an `Abort` (`src/athc/cli/__init__.py`).
- **A value out of range is a usage error in plain words, from a callback.** Click's `IntRange` was the rejected way: it adds `  [0<=x<=2147483647]` after the option's help text (`core.py`, `get_help_extra`, `get_help_record`) and calls a non-integer `'1.5' is not a valid integer range.` (`types.py`, `IntRange.name`), neither of them plain words for an end user (cli-help.md rule 9). autocontinue-cli.md decision 4 bounds a value with a plain `int` type and an athc callback raising `click.BadParameter` inside Click's `Invalid value for '<option>':` frame, lowercase, ending in a period (architecture.md, Wording); this plan does the same. Plain `int` keeps Click's `'abc' is not a valid integer.` for a non-integer, and Click's parser takes `-1` after `--seed` as the value, so the callback sees it.
- **Output files land in the current folder and their names are printed.** git format-patch: "If -o is specified, output files are created in <dir>. Otherwise they are created in the current working directory." "The names of the output files are printed to standard output, unless the --stdout option is specified." athc's `OK   <file>` lines do the same; athc's output rule: "in the current directory (`generate-schedule`)" and "An existing file at the path is replaced." (`docs/design/architecture.md`, Output files).
- **Not every command is in the default list.** git help: "With no options and no <command> or <doc> given, the synopsis of the git command and a list of the most commonly used Git commands are printed on the standard output." "If the option --all or -a is given, all available commands are printed on the standard output." Click's `hidden`: "hide this command from help outputs" (`core.py`).
- **Brief success output; the default right for most users.** clig.dev: "Display output on success, but keep it brief." "Make the default the right thing for most users." "Confirm before doing anything dangerous."

## 4. Decisions

1. **No coach runs it; the command stays hidden and stays out of COMMANDS.txt.** Section 2 has the evidence. git lists only its common commands by default and keeps the rest reachable; Click's `hidden` does the same, and `-h` keeps working on it, as today. SCHEDULER-COMMANDS.txt stays its document.
2. **A leaf command named `generate-schedule`.** One action, so no group (cli-help.md: groups are nouns with several verbs); the verb-noun hyphenated name matches `check-ppp` and `convert-pdb`, and cli-help.md keeps it.
3. **`--season YEAR` stays a required option, and a bare command is Click's `Missing option '--season'.`** The year is a value, not a path, so it does not join the positional-PATH rule of the file commands (check-ppp-cli.md decision 16); a named option reads in a script and in the report's command line (clig.dev: prefer flags; Azure CLI's required `--name`). Usage errors stay Click's (architecture.md), so the message is not reworded. The year names the `[renames.<season>]` table and the output files, and the league files carry no readable season (section 1), so nothing could stand in for it.
4. **No default season.** A season is not a setting, and the files cannot say which one they belong to, so a guessed year would write a full file set under the wrong name. A required option is the confirmation (clig.dev: "Confirm before doing anything dangerous").
5. **`--previous FILE` takes the previous season's `.lge` file itself and is optional: without it, the standings come from the `--upcoming` file, one file for both, and `[renames.<season>]` is ignored (decided 2026-10-13).** The file is the previous season's, saved after the last playoff game (the Commissioner's archive, one folder per season); nothing in config names it, and no fixed place could: the league's `path` folder holds a finished season only until the game rolls over. A named option rather than a positional because both files are named `<league>.lge` and only the name says which is the previous season (clig.dev: prefer flags). The placeholder is `FILE` (cli-help.md rule 26).
6. **`--upcoming FILE` takes the upcoming season's `.lge` file itself and defaults to `<path>\<league>.lge`, `path` from `league.toml`.** What the option must point at is the file the game will play the upcoming season from, the one with the new conferences, divisions and names, wherever its folder is. `path` is the default because it is the folder athc already treats as holding the league's current files (check-ppp reads its `.lg2` and `.lge` there; a copy of the game's folder is fine, check-ppp-cli.md section 5), and once the Commissioner has rolled the game over, the `.lge` there is the upcoming season's. So no `--upcoming` means `<path>\<league>.lge` (the configured source) and an explicit file overrides it; the placeholder is `FILE` (cli-help.md rule 26). With neither, the line gives the way out: `FAIL <league.toml>: League files folder is not set. Run 'athc config set path FOLDER' or pass --upcoming.`, cli-help.md rule 21's hint with this command's own ending. The line is this command's own literal (`generate_schedule.py` line 136); `check_ppp.py` line 196 prints the same words from its own literal and gets its own alternative (`--all-teams`, rule 21).
7. **No season check on the files; a wrong-season `--previous` shows only through its names.** The `.lge` header has a base year but no documented count of the seasons completed (`lge.md`, the L03 table), so a file's season cannot be read. An unfinished `--previous` is the `Season not finished` `WARN` (decision 9); a finished file of another season fails as `Team(s) not in <upcoming>: ...` with the `[renames.<season>]` hint when its names differ, and is otherwise the Commissioner's to get right, with the report's Command line row recording both files. The upcoming file may hold played games: the golden case's upcoming file is the real 2048 file after week 1 (`tests/integration/league_files.py`).
8. **A missing or broken league file keeps the read's own line, and the two files are read before anything long.** A file whose folder is absent is `FAIL <folder>\PNFL.lge: The system cannot find the path specified.`, a file missing from a folder that exists `... The system cannot find the file specified.` (the `FileNotFoundError` from `read_bytes`, worded by `reason_of` and `missing_reason`, section 1), a broken file the lge library's line, each naming the file; no pre-check is added, since the read is the first thing done with the file and already says what is wrong in Windows' words. The previous file is read first, then the upcoming, then the checks between them, in the code's order.
9. **An unfinished season is a `WARN`, not a `FAIL`: `WARN <file>: Season not finished: <n> game(s) not played.`, and the run goes on with the games played.** A noted oddity that may be intended is a `WARN` (section 3), and a `WARN` never changes the exit code (architecture.md). A new league with no games played needs no rule of its own: every team is level at every step, so the coin toss (decision 10) orders them.
10. **The last tiebreak, for the division finish and for the overall order, is a coin toss drawn from the run's seed; the overall order is playoff finish, regular-season win percentage, strength of schedule, the previous season's division finish, point differential, coin toss.** The NFL's last tiebreaker is a coin toss, as is the game's own (step 8 in `docs/design/fbpro98-game-behavior.md`, Tie-breakers). The coin toss replaces the league file's team order, so no file's order breaks a tie anywhere.
11. **`--seed NUMBER` takes 0 to 2147483647, checked by an athc callback; no seed draws one from 0 to 1,000,000, as today, and the result line shows it.** CP-SAT's seed is a 32-bit integer and the pybind setter refuses anything larger with a `TypeError`, which today ends as an "Unexpected error" line, a bug report for a typo. A seed is a whole number from 0 up, the range athc's own draw uses, so the lower bound is 0 (the setter takes -1, but no draw or document ever uses a negative seed). The callback raises Click's `BadParameter` inside its `Invalid value for '--seed':` frame, in plain words (`must be 0 to 2147483647, got -1.`), the shape autocontinue-cli.md decision 4 uses; Click's `IntRange` was rejected because its help suffix and its `integer range` wording are not plain words (section 3). Printing the seed is pytest-randomly's pattern and already athc's.
12. **`--time-limit LIMIT` stays an integer, now 1 or more, checked by a callback of the same shape (`must be 1 or more, got 0.`), with no maximum, and keeps replacing `time_limit` (phase 2) only; the file's `time_limit` and `phase1_time_limit` must be positive numbers.** The integer type is pinned by `test_rejects_non_integer_time_limit`, and the shipped budgets are whole numbers (120, 300, 600), so a value below 1 is a typo against them. What the solver does with one: a one-variable CP-SAT model solved with `max_deterministic_time = 0.0` returns `UNKNOWN` and with `-1.0` returns `MODEL_INVALID` (run against the venv's OR-Tools 9.15.6755), and today either ends as `SchedulerError` from `schedule_builder.py` after a full phase-1 solve. No maximum: the parameter is a `double`, and a larger budget only lets the search run longer. The same budget in `scheduler.toml` gets the same rule, one validator for both solver keys (`[solver] time_limit: Must be a positive number.`), as `_workers` already demands a positive integer; `[difficulty] spread` stays as it is, since `0.0` is "flat" by the shipped comment. Phase 1 keeps its own file key: the long solve is phase 2 (300 or 600 against 120), and a Commissioner changing phase 1 edits `scheduler.toml`, where both keys sit together.
13. **No `--workers` or other solver flag.** `solver_workers` is a reproducibility contract: the same seed gives the same schedule only at the same worker count, so it stays in `scheduler.toml` where the report can name it ("Not CLI-overridable", `src/athc/scheduler/config.py` and `docs/scheduler/ARCHITECTURE.md`; `test_no_worker_count_override`).
14. **Inputs are the league folder's `scheduler.toml` and the two league files; no PATH, no team.** The league files are the Commissioner's, named by the league and chosen by season, not files a coach keeps in a working folder, so check-ppp-cli.md's default team (`team` and `ppp_path` in `league.toml`, `--team NAME`; decisions 4 and 5) does not apply, and only the path rule's configured default and override (cli-help.md rule 16) do, on `--upcoming` (decision 6). `--league NAME` stays, with cli-help.md rule 10's shared text.
15. **Output stays the current folder, the names stay `schedule_YEAR_DATE_TIME`, and a same-minute rerun replaces the files; no `-o`.** architecture.md's output rule names the current folder for generate-schedule, and git format-patch's default is the same; the Commissioner changes to the folder first. Replacing is architecture.md's rule for an existing file, and a solve takes minutes, so two runs rarely end in one minute. These plans serve coach workflows only (the user's request for them), so an output option, which no coach workflow needs, is not added.
16. **No folder check before the solve (decided 2026-10-13).** A folder that refuses writes fails when the files are written, as today: a check at the start cannot promise the later write, so it would only add a second place for the same error.
17. **Ctrl+C anywhere in the run is `FAIL Interrupted.`, exit 130, nothing written: CP-SAT's own Ctrl+C is turned off and a console handler stops the search.** The probe (sections 1 and 3) settled the three ways. With `catch_sigint_signal` on, as today, the first press during a solve ends the process at once with no line, because OR-Tools keeps its handler in a `thread_local` set on the solving thread and Windows runs the Ctrl+C handler on a thread of its own, where it is empty. With the flag off alone, the press waits for the budget: the solve is a C calculation and Python's handler runs only when it returns (the probe: `KeyboardInterrupt` after the full 20 s), so a real run would wait up to the whole phase budget before stopping, though it would then stop properly. With the flag off and a console control handler installed for the solve that calls `CpSolver.stop_search()`, the search ended at the press, the process went on and Python's handler stayed in place. So `make_solver` sets `catch_sigint_signal = False`, and one solve helper beside it (`utils.py`), which both builders call, installs the handler through `ctypes` (`kernel32.SetConsoleCtrlHandler`) for the length of `solver.solve()`, removes it after, and raises `KeyboardInterrupt` when it fired; Click turns that into `Abort` and the one place prints `FAIL Interrupted.` and exits 130 with nothing written, the meaning Ctrl+C has in every other athc command (architecture.md's exit table). Outside a solve, Python's own handler does the same, since the flag off leaves it in place. The best schedule found so far is not kept: a press means stop, and a Commissioner who wants a shorter solve sets `--time-limit`. The phase-2 progress line stays as today.
18. **Lines and codes stay the project's.** Progress on stderr, `WARN` on stderr, `OK` per file and the tally line on stdout, 0 or 2, never 1, 130 on Ctrl+C (architecture.md, Console and Exit codes). The new lines are the "League files folder is not set" line, the `Season not finished` `WARN`, the two bound errors and the file's positive-number error.

## 5. The command

Click 8.4.1's own rendering at its 78 columns, with `-h` from athc's `CONTEXT_SETTINGS`, in cli-help.md's style (the epilog prints verbatim; its second line is 74 columns with its indent):

```
Usage: athc generate-schedule [OPTIONS]

  Generate a league's season schedule and report.

  Reads the standings from --previous FILE (default: the --upcoming file) and
  the conferences, divisions and team names from --upcoming FILE (default: the
  league's .lge in path in league.toml), then writes a .txt and .html schedule
  plus an .html report to the current folder, named schedule_YEAR_DATE_TIME.

Options:
  --season YEAR       Season to schedule, e.g. 2048.  [required]
  --previous FILE     Previous season's .lge file, saved after its last
                      playoff game (default: the --upcoming file).
  --upcoming FILE     Upcoming season's .lge file (default: the league's .lge
                      in path in league.toml).
  --seed NUMBER       Seed for a repeatable run (default: random; the last
                      line shows it).
  --time-limit LIMIT  Solver budget for placing games into weeks, in the
                      solver's own time units, not seconds (default:
                      time_limit in scheduler.toml).
  --league NAME       League to use (default: the one set with athc config set
                      league).
  -h, --help          Show this message and exit.

  Examples:

    athc generate-schedule --season 2050 --previous E:\PNFL\2049\PNFL.lge
    athc generate-schedule --season 2030 --league PCFL --previous PCFL.lge
```

### Inputs

| Input | Where | Needed | What is missing or wrong |
|---|---|---|---|
| the previous season's `.lge` | `--previous FILE`, else the upcoming file | no, the upcoming file stands in | absent folder or file: Windows' phrase naming the file; broken: the lge library's line; unfinished: the `WARN` `Season not finished: <n> game(s) not played.`, then the run; a team with no upcoming match: `Team(s) not in <upcoming>: ... List renamed teams under [renames.YEAR] in <scheduler.toml>.` |
| the upcoming season's `.lge` | `--upcoming FILE`, else `<league>.lge` in `path` from `league.toml`, else the "League files folder is not set" line | yes | as above for absent or broken, and for unfinished when it gives the standings; a team with no previous match: `Team(s) not in <previous>: ...`; not two conferences of nine: the structure error naming it |
| `scheduler.toml` | the league folder | no, every key defaults | bad TOML or a bad value: `FAIL <file>: ...`, as today; a bad `[renames.YEAR]` entry: its line naming the table and key; `time_limit` or `phase1_time_limit` at 0 or below: the positive-number line (decision 12) |
| `league.toml`, `path` | the league folder | unless `--upcoming` | `FAIL <league.toml>: League files folder is not set. Run 'athc config set path FOLDER' or pass --upcoming.` |
| `athc.ini`, `[athc] league` | the config folder | unless `--league` | `FAIL No league selected. Run 'athc config set league NAME' or pass --league. Available: ...`, as today |

- **The two files:** `--upcoming` names the upcoming season's file, else `<league>.lge` in `path`; `--previous` names the previous season's file, else the upcoming file gives the standings too.
- **Order of output:** nothing until the two files and `scheduler.toml` are read, then the `Season not finished` `WARN`, if any; then the progress lines on stderr in the order the solve runs (`Generating the <season> schedule`, `Phase 1: ...`, `Phase 2: ...`), then the three `OK   <file>` lines on stdout in the order written (`.txt`, `.html`, `_report.html`), then `Generated <n> games (seed <s>)`. An error stops the run at its line; nothing is written before the solve ends.
- **Output folder:** the current folder; the three names share one minute stamp, and a file of the same name is replaced.
- **Ctrl+C:** anywhere in the run, `FAIL Interrupted.`, 130, nothing written; during a solve the search stops at the press (decision 17).
- **Argument errors:** Click's, exit 2: a missing `--season`, `--upcoming` without a value (`Option '--upcoming' requires an argument.`), a value that is not an integer, a seed outside 0 to 2147483647, a time limit under 1, an unknown option (`No such option '--workers'.`).
