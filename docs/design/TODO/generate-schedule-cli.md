# generate-schedule CLI plan

**Goal:** `athc generate-schedule --season YEAR --previous FOLDER` builds a league's season schedule from two of the game's own league files, the previous season's `.lge` (saved after its last playoff game, for the standings) and the upcoming season's (for the conferences, divisions and team names; by default the league's `path` folder), and writes a `.txt` and `.html` schedule plus an `.html` report to the current folder. It is the Commissioner's tool: hidden from the command list, documented in SCHEDULER-COMMANDS.txt, and no coach runs it. The command keeps its shape; this plan fits its help to cli-help.md, settles the two folder options' rules, warns when one folder plays both parts, bounds `--seed` and `--time-limit` so a bad value is a usage error instead of a solver failure, checks that the current folder takes a file before the long solve, and makes Ctrl+C stop the run the way it stops every other athc command.

**Status:** proposal, 2026-10-13; nothing changed yet. Every choice is decided below, with its reason next to it. Depends on cli-help.md landing first (its rule 25). Describes the code at main `dade898` (standings and structure from the league's `.lge` files). Reviewed in six rounds; the findings are folded in.

The limits are CP-SAT deterministic time, not seconds (`make_solver` in `src/athc/scheduler/schedulers/utils.py` sets `max_deterministic_time`). Shipped values: PNFL `time_limit = 600.0`, PCFL `300.0`, both `phase1_time_limit = 120.0`; the built-in defaults are 300 and 120. The file loader (`_number`) checks only that the value is a number, so `0` and negatives pass.

The seed goes to CP-SAT's `random_seed`, a 32-bit integer (`optional int32 random_seed = 31`; descriptor type `TYPE_INT32`). `CpSolver.parameters` is the pybind object `cp_model_helper.SatParameters` (`ortools/sat/python/cp_model.py` line 1746), whose setter refuses 2147483648 with a `TypeError` ("incompatible function arguments"; run against the venv's OR-Tools 9.15.6755, which accepts -1 and 2147483647). - Output: `schedule_<season>_<YYYYMMDD_HHMM>.txt`, `.html` and `_report.html` in the current folder (`Path.cwd()`), written last, with `write_text`, so a file of the same name is replaced; a second run that ends in the same minute replaces the first. Nothing checks that the current folder takes a file before the solve: in a folder that refuses writes, the run solves for minutes and then fails with `FAIL <file>: Access is denied.` (`test_errors_on_oserror` stubs the whole run). The report records the scheduler, difficulty spread, seed, CPU, thread count, command line, config path and elapsed wall-clock time (`src/athc/scheduler/writers/report.py`); no solver status.
- Lines: progress on stderr (`Generating the 2048 schedule`, `Phase 1: selecting matchups`, `Phase 2: placing games into weeks. This usually takes several minutes and can take 30 minutes or more.`), then `OK   <file>` per file on stdout and the result line `Generated <n> games (seed <s>)`. Exit 0 written, 2 for any error: usage, league, a league file, bad `scheduler.toml`, the cross checks (`weeks`, `opening_nonconference_weeks`, `[rivalries]`), `SchedulerError` (`CP-SAT returned status INFEASIBLE - no feasible schedule.`), an `OSError` while writing, `Missing ortools. Reinstall athc.`. It never exits 1: it is not a checker.
- Ctrl+C: during a solve it kills the process. `make_solver` leaves CP-SAT's `catch_sigint_signal` at its default, true ("If set, catching the SIGINT signal will terminate the search gracefully, as if a time limit was reached", `sat_parameters.proto`), but that promise does not hold on Windows: OR-Tools' handler store is `thread_local static std::function<void()> handler_;` (`ortools/util/sigint.h`), filled by `Register` on the solving thread, while Windows runs a Ctrl+C handler on a thread of its own ("When a CTRL+C interrupt occurs, Win32 operating systems generate a new thread to specifically handle that interrupt", MS Learn `signal`), where that store is empty. A standalone probe (a Golomb-ruler CP-SAT model with a 20 s budget on one worker, `CTRL_C_EVENT` sent 4 s in, the venv's OR-Tools 9.15.6755) showed the first press ending the process at once: exit code 0xC0000409 (3221226505), no output, so in athc no `FAIL` line and no `exit` line in the run log. After a solve that was not interrupted, the C runtime's SIGINT handler is the default, not Python's (OR-Tools' destructor sets `signal(SIGINT, SIG_DFL)`, `sigint.cc`; read through `ucrtbase.signal`), so a Ctrl+C between the phases, while phase 2's model is built or while the three files are written also ends the process with Windows' own code and no athc line. Only a Ctrl+C before phase 1's solve reaches the one place as Click's `Abort`: `FAIL Interrupted.`, 130. No document says any of this.
- Docs: `docs/scheduler/README.md`, `docs/scheduler/ARCHITECTURE.md`, `config/release/docs/SCHEDULER-COMMANDS.txt` ("Commissioner only"; "intentionally left out of the general COMMANDS.txt"; "The previous season's <league>.lge (saved after its last playoff game) gives the standings"). `STATUS.md`'s scheduler section still says every run "writes to a new timestamped folder, so nothing is overwritten" (line 434); the code writes three files named to the minute in the current folder.

## 3. What other tools do

- **A required value is a named option, and two inputs with different parts are two named options.** clig.dev: "Prefer flags to args." "It's a bit more typing, but it makes it much clearer what is going on." Azure CLI's `az group create` lists `--location` and `--name` under "Required Parameters" and shows them in its usage without brackets. The two folders here each hold a file of the same name, `<league>.lge`, so only the option names say which season is which. Click marks a required option `[required]` at the end of its help line (`core.py`, `get_help_record`) and refuses a run without it with `Missing option '--season'.` (`exceptions.py`, `MissingParameter`).
- **A configured default folder, an override, and `.` for the current folder.** cli-help.md rule 16 (from check-ppp-cli.md decision 3): no path means the configured default, `.` the current folder, an explicit path overrides both (check-ppp's precedents: pytest's `testpaths`, mypy's `files`, pyright's `include`, ruff's `[default: .]`). athc's `playpool check` takes no argument for the league's `play_path` or a folder instead.
- **A noted oddity that may be intended is a `WARN`.** architecture.md's message kinds: `WARN` is "noted, nothing failed", on stderr, never changing the exit code; `collect_files` gives `WARN <dir>: No .pln files.` for a folder with nothing to do and the run goes on.
- **The "No path" line names the command's own way out.** cli-help.md rule 21: `FAIL <league.toml>: No path for the league. Set path in this file, or pass <alternative>.`, "the alternative being the command's own path form"; check-ppp-cli.md section 7 ends its path lines the same way (`Set ppp_path in <league.toml>, or pass the folder.`), so a first run shows the way out on the first line.
- **The seed is printed so a run can be repeated.** pytest-randomly: "The output will start with an extra line that tells you the random seed that is being used:" `Using --randomly-seed=1553614239`. athc's result line `Generated <n> games (seed <s>)` and the report's Seed row do the same.
- **The solver's own time units.** OR-Tools `sat_parameters.proto`, `max_deterministic_time`: "Maximum time allowed in deterministic time to solve a problem." "The deterministic time should be correlated with the real time used by the solver, the time unit being as close as possible to a second." It is a `double`, so any budget is taken and a larger one only lets the search run longer. `random_seed` is "optional int32 random_seed = 31 [default = 1];".
- **CP-SAT's own Ctrl+C does not work on Windows; a console handler that stops the search does.** `catch_sigint_signal`: "Indicates if the CP-SAT layer should catch Control-C (SIGINT) signals when calling solve. If set, catching the SIGINT signal will terminate the search gracefully, as if a time limit was reached." "optional bool catch_sigint_signal = 135 [default = true];" (`sat_parameters.proto`). `ortools/util/sigint.h`: "thread_local static std::function<void()> handler_;" and "static void SigHandler(int s);"; `sigint.cc`: `Register` ends with "signal(SIGINT, &SigHandler);", the handler is "void SigintHandler::SigHandler(int) { handler_(); }", the destructor "if (handler_ != nullptr) signal(SIGINT, SIG_DFL);". MS Learn `signal`: "SIGINT is not supported for any Win32 application. When a CTRL+C interrupt occurs, Win32 operating systems generate a new thread to specifically handle that interrupt." The probe (section 1): with the flag on, the first press ends the process at once, exit code 0xC0000409, no output; with the flag off, the press is deferred (Python's `signal` docs: "A long-running calculation implemented purely in C ... may run uninterrupted for an arbitrary amount of time, regardless of any signals received. The Python signal handlers will be called when the calculation finishes."): the solve ran to its 20 s budget and `KeyboardInterrupt` followed, and the C runtime's handler was still Python's afterwards; with the flag off and a console control handler installed through `ctypes` (`kernel32.SetConsoleCtrlHandler`) that calls `CpSolver.stop_search()` ("Stops the current search asynchronously.", `cp_model.py` lines 1781-1785) and returns true, the solve returned `FEASIBLE` at the press (3.6 s into a 20 s budget), the process went on, Python saw no `KeyboardInterrupt`, and its handler was intact. Click turns a `KeyboardInterrupt` out of a command into `Abort` whatever the mode (`core.py` lines 1456-1458), and the one place prints `FAIL Interrupted.` and exits 130 for an `Abort` (`src/athc/cli/__init__.py`).
- **A value out of range is a usage error in plain words, from a callback.** Click's `IntRange` was the rejected way: it adds `  [0<=x<=2147483647]` after the option's help text (`core.py`, `get_help_extra`, `get_help_record`) and calls a non-integer `'1.5' is not a valid integer range.` (`types.py`, `IntRange.name`), neither of them plain words for an end user (cli-help.md rule 9). autocontinue-cli.md decision 4 bounds a value with a plain `int` type and an athc callback raising `click.BadParameter` inside Click's `Invalid value for '<option>':` frame, lowercase, ending in a period (architecture.md, Wording); this plan does the same. Plain `int` keeps Click's `'abc' is not a valid integer.` for a non-integer, and Click's parser takes `-1` after `--seed` as the value, so the callback sees it.
- **Output files land in the current folder and their names are printed.** git format-patch: "If -o is specified, output files are created in <dir>. Otherwise they are created in the current working directory." "The names of the output files are printed to standard output, unless the --stdout option is specified." athc's `OK   <file>` lines do the same; athc's output rule: "in the current directory (`generate-schedule`)" and "An existing file at the path is replaced." (`docs/design/architecture.md`, Output files).
- **Check the place a long run writes to before the run, with a real file.** athc's own rule: "A log folder that cannot be created or written is one `FAIL <path>: <reason>` line and exit 2 before anything runs." (`docs/design/architecture.md`, Run log). `os.access` is not the check: "I/O operations may fail even when access() indicates that they would succeed" (`os` docs), and on this machine `os.access(r"C:\Windows\System32", os.W_OK)` is `True` while a file cannot be made there. `tempfile.TemporaryFile` is not the check either: on Windows it is `NamedTemporaryFile` (`Lib\tempfile.py` lines 600-603) and `_mkstemp_inner` turns a `PermissionError` into `continue` whenever `os.access(dir, W_OK)` is true (lines 260-265), for `TMP_MAX` tries, so in a folder that refuses writes it loops instead of failing. One `os.open` with `O_RDWR | O_CREAT | O_EXCL | O_TEMPORARY` fails at once: `PermissionError` (errno 13, no Windows code) in `C:\Windows\System32`, `FileNotFoundError` (errno 2) in an absent folder, which athc's `reason_of` words as `Access is denied.` and `The system cannot find the path specified.` (probed with the venv's Python 3.13.7 on 2026-10-13); `O_TEMPORARY` removes the file when it is closed, and `O_EXCL` makes a file already there a `FileExistsError`.
- **Not every command is in the default list.** git help: "With no options and no <command> or <doc> given, the synopsis of the git command and a list of the most commonly used Git commands are printed on the standard output." "If the option --all or -a is given, all available commands are printed on the standard output." Click's `hidden`: "hide this command from help outputs" (`core.py`).
- **Brief success output; the default right for most users.** clig.dev: "Display output on success, but keep it brief." "Make the default the right thing for most users." "Confirm before doing anything dangerous."

## 4. Decisions

1. **No coach runs it; the command stays hidden and stays out of COMMANDS.txt.** Section 2 has the evidence. git lists only its common commands by default and keeps the rest reachable; Click's `hidden` does the same, and `-h` keeps working on it, as today. SCHEDULER-COMMANDS.txt stays its document.
2. **A leaf command named `generate-schedule`.** One action, so no group (cli-help.md: groups are nouns with several verbs); the verb-noun hyphenated name matches `check-ppp` and `convert-pdb`, and cli-help.md keeps it.
3. **`--season YEAR` stays a required option, and a bare command is Click's `Missing option '--season'.`** The year is a value, not a path, so it does not join the positional-PATH rule of the file commands (check-ppp-cli.md decision 16); a named option reads in a script and in the report's command line (clig.dev: prefer flags; Azure CLI's required `--name`). Usage errors stay Click's (architecture.md), so the message is not reworded. The year names the `[renames.<season>]` table and the output files, and the league files carry no readable season (section 1), so nothing could stand in for it.
4. **No default season.** A season is not a setting, and the files cannot say which one they belong to, so a guessed year would write a full file set under the wrong name. A required option is the confirmation (clig.dev: "Confirm before doing anything dangerous").
5. **`--previous FOLDER` stays a required named option with no default.** It names the folder holding the previous season's league files, saved after the last playoff game (the Commissioner's archive, one folder per season); nothing in config names that folder, and no fixed place could: the league's `path` folder holds a finished season only until the game rolls over, and after that its file is `Season not finished` (`test_cli_errors_when_the_previous_season_is_not_finished`). A named option rather than a positional because both folders hold a `<league>.lge` and only the name says which is the previous season (clig.dev: prefer flags). `.` is a folder like any other (`Path(".") / "PNFL.lge"` reads `PNFL.lge`, so a line about it names the file alone, as `type PNFL.lge` would).
6. **`--upcoming FOLDER` keeps its default, `path` in `league.toml`, and follows the path rule.** What the option must point at is the file the game will play the upcoming season from, the one with the new conferences, divisions and names, wherever its folder is. `path` is the default because it is the folder athc already treats as holding the league's current files (check-ppp reads its `.lg2` and `.lge` there; a copy of the game's folder is fine, check-ppp-cli.md section 5), and once the Commissioner has rolled the game over, the `.lge` there is the upcoming season's. So no `--upcoming` means `path` (the configured source), `.` means the current folder, and an explicit folder overrides both, cli-help.md rule 16's path rule word for word (check-ppp-cli.md decision 3). With neither, the line gains the way out: `FAIL <league.toml>: No path for the league. Set path in this file, or pass --upcoming.`, cli-help.md rule 21's hint with this command's own path form as the alternative. The line is this command's own literal (`generate_schedule.py` line 136); `check_ppp.py` line 196 prints the same words from its own literal and gets its own alternative (`--all-teams`, rule 21).
7. **One folder named by both options is a `WARN`, not an error.** After the folders are known and before anything is read, the command compares them by resolved path (`Path.resolve()`, as `collect_files` already deduplicates) and prints `WARN <folder>\PNFL.lge: Named by both --previous and --upcoming.` on stderr, the folder spelled as `--previous` was given, then runs on. The run is not impossible: before the game's rollover the folder holding the league's files is both the finished season and the only structure there is, and `--previous <path>` with the default `--upcoming` is exactly that case; after the rollover the same folder goes on to `Season not finished`, as today, with the `WARN` before it. It is worth a line because a schedule built from one folder carries that season's names, and the import file's team names must match the game's (`schedule_format.md`: "Team names are exact"). A `WARN` never changes the exit code (architecture.md).
8. **No season check on the files; a wrong-season `--previous` shows only through its names.** The `.lge` header has a base year but no documented count of the seasons completed (`lge.md`, the L03 table), so a file's season cannot be read. An unfinished `--previous` is `Season not finished`, as today; a finished file of another season fails as `Team(s) not in <upcoming>: ...` with the `[renames.<season>]` hint when its names differ, and is otherwise the Commissioner's to get right, with the report's Command line row recording both folders. The upcoming file may hold played games: the golden case's upcoming file is the real 2048 file after week 1 (`tests/integration/league_files.py`).
9. **A missing or broken league file keeps the read's own line, and the two files are read before anything long.** An absent folder is `FAIL <folder>\PNFL.lge: The system cannot find the path specified.`, a folder without the file `... The system cannot find the file specified.` (the `FileNotFoundError` from `read_bytes`, worded by `reason_of` and `missing_reason`, section 1), a broken file the lge library's line, each naming the file; no pre-check is added, since the read is the first thing done with the folder and already says what is wrong in Windows' words. The previous file is read first, then the upcoming, then the checks between them, in the code's order.
10. **`--seed NUMBER` takes 0 to 2147483647, checked by an athc callback; no seed draws one from 0 to 1,000,000, as today, and the result line shows it.** CP-SAT's seed is a 32-bit integer and the pybind setter refuses anything larger with a `TypeError`, which today ends as an "Unexpected error" line, a bug report for a typo. A seed is a whole number from 0 up, the range athc's own draw uses, so the lower bound is 0 (the setter takes -1, but no draw or document ever uses a negative seed). The callback raises Click's `BadParameter` inside its `Invalid value for '--seed':` frame, in plain words (`must be 0 to 2147483647, got -1.`), the shape autocontinue-cli.md decision 4 uses; Click's `IntRange` was rejected because its help suffix and its `integer range` wording are not plain words (section 3). Printing the seed is pytest-randomly's pattern and already athc's.
11. **`--time-limit LIMIT` stays an integer, now 1 or more, checked by a callback of the same shape (`must be 1 or more, got 0.`), with no maximum, and keeps replacing `time_limit` (phase 2) only; the file's `time_limit` and `phase1_time_limit` must be positive numbers.** The integer type is pinned by `test_rejects_non_integer_time_limit`, and the shipped budgets are whole numbers (120, 300, 600), so a value below 1 is a typo against them. What the solver does with one: a one-variable CP-SAT model solved with `max_deterministic_time = 0.0` returns `UNKNOWN` and with `-1.0` returns `MODEL_INVALID` (run against the venv's OR-Tools 9.15.6755), and today either ends as `SchedulerError` from `schedule_builder.py` after a full phase-1 solve. No maximum: the parameter is a `double`, and a larger budget only lets the search run longer. The same budget in `scheduler.toml` gets the same rule, one validator for both solver keys (`[solver] time_limit: Must be a positive number.`), as `_workers` already demands a positive integer; `[difficulty] spread` stays as it is, since `0.0` is "flat" by the shipped comment. Phase 1 keeps its own file key: the long solve is phase 2 (300 or 600 against 120), and a Commissioner changing phase 1 edits `scheduler.toml`, where both keys sit together.
12. **No `--workers` or other solver flag.** `solver_workers` is a reproducibility contract: the same seed gives the same schedule only at the same worker count, so it stays in `scheduler.toml` where the report can name it ("Not CLI-overridable", `src/athc/scheduler/config.py` and `docs/scheduler/ARCHITECTURE.md`; `test_no_worker_count_override`).
13. **Inputs are the league folder's `scheduler.toml` and the two league files; no PATH, no team.** The league files are the Commissioner's, named by the league and chosen by season, not files a coach keeps in a working folder, so check-ppp-cli.md's default team (`team` and `ppp_path` in `league.toml`, `--team NAME`; decisions 4 and 5) does not apply, and only the path rule (cli-help.md rule 16; check-ppp-cli.md decision 3) does, on `--upcoming` (decision 6). `--league NAME` stays, with cli-help.md rule 10's shared text.
14. **Output stays the current folder, the names stay `schedule_YEAR_DATE_TIME`, and a same-minute rerun replaces the files; no `-o`.** architecture.md's output rule names the current folder for generate-schedule, and git format-patch's default is the same; the Commissioner changes to the folder first. Replacing is architecture.md's rule for an existing file, and a solve takes minutes, so two runs rarely end in one minute. These plans serve coach workflows only (the user's request for them), so an output option, which no coach workflow needs, is not added. A run with `--upcoming .` writes its three files into that same folder, beside the league files, since the current folder is both.
15. **The current folder is checked before the solve, with one hand-opened file named for the process.** A solve takes minutes (the phase-2 progress line says so), and a folder that refuses writes is found today only when the files are written, with the solve lost. Before the solve, after the league is built from the two files, the writer (`main.generate_schedule`, since whatever writes the file makes the call, architecture.md) opens and closes one probe file in the output folder, `athc-probe-<pid>.tmp` with the process id from `os.getpid()`, with `os.open(..., O_RDWR | O_CREAT | O_EXCL | O_TEMPORARY)`, which Windows removes on close. A `FileExistsError` counts as writable: the folder holds a file of that name, so it takes files, and a leftover needs a crashed earlier process with the same id. Any other `OSError` becomes `AthcError(reason, output_dir)` with `reason_of`'s phrase, plus the hint `Run from a folder you can write to.` when the phrase is `Access is denied.` (the other case, a folder that is gone, already says what is wrong). `tempfile.TemporaryFile` is not used, since on Windows it retries through a `PermissionError` for as long as `os.access` says the folder is writable, which it always says (section 3); `os.access` alone is not used for the same reason.
16. **Ctrl+C anywhere in the run is `FAIL Interrupted.`, exit 130, nothing written: CP-SAT's own Ctrl+C is turned off and a console handler stops the search.** The probe (sections 1 and 3) settled the three ways. With `catch_sigint_signal` on, as today, the first press during a solve ends the process at once with no line, because OR-Tools keeps its handler in a `thread_local` set on the solving thread and Windows runs the Ctrl+C handler on a thread of its own, where it is empty. With the flag off alone, the press waits for the budget: the solve is a C calculation and Python's handler runs only when it returns (the probe: `KeyboardInterrupt` after the full 20 s), so a real run would wait up to the whole phase budget before stopping, though it would then stop properly. With the flag off and a console control handler installed for the solve that calls `CpSolver.stop_search()`, the search ended at the press, the process went on and Python's handler stayed in place. So `make_solver` sets `catch_sigint_signal = False`, and one solve helper beside it (`utils.py`), which both builders call, installs the handler through `ctypes` (`kernel32.SetConsoleCtrlHandler`) for the length of `solver.solve()`, removes it after, and raises `KeyboardInterrupt` when it fired; Click turns that into `Abort` and the one place prints `FAIL Interrupted.` and exits 130 with nothing written, the meaning Ctrl+C has in every other athc command (architecture.md's exit table). Outside a solve, Python's own handler does the same, since the flag off leaves it in place. The best schedule found so far is not kept: a press means stop, and a Commissioner who wants a shorter solve sets `--time-limit`. The phase-2 progress line stays as today.
17. **Lines and codes stay the project's.** Progress on stderr, `WARN` on stderr, `OK` per file and the tally line on stdout, 0 or 2, never 1, 130 on Ctrl+C (architecture.md, Console and Exit codes). The new lines are the `--upcoming` hint, the same-folder `WARN`, the two bound errors, the folder check and the file's positive-number error.
18. **Setup order: arguments, league and its `league.toml`, league folder, the upcoming folder (`--upcoming`, else `path`), the same-folder `WARN`, `scheduler.toml`, the previous file, the upcoming file, the checks between them, the output folder, the cross checks, the solver, the files.** This is the code's order (`generate_schedule.py` then `main.py` then `league_files.py` then `scheduler.py`) with the `WARN` and the folder check added; the bound checks are Click's callbacks and come first. A broken install (`Missing ortools`) shows after the files are read, when the solver is imported.
19. **Help follows cli-help.md, which lands first:** `[OPTIONS]`, `--season YEAR`, `--previous FOLDER`, `--upcoming FOLDER` (rule 3: `FOLDER` is a folder only), `--seed NUMBER`, `--time-limit LIMIT`, `--league NAME`, "folder", the solver's time units in plain words, a summary under 55 characters starting with a verb, a description of four lines naming the options and the placeholder in caps, an Examples epilog (rules 1, 2, 3, 5, 6, 9, 10, 13, 14). The description says "the league's .lge file" instead of today's `<league>.lge`, plain words for the one file both folders hold. The bounds on `--seed` and `--time-limit` are callbacks, not `IntRange`, so no range suffix follows their help text and a non-integer keeps Click's `is not a valid integer.`; the bounds are said in the error lines, in plain words (autocontinue-cli.md decision 4; cli-help.md rule 9). The pointer to `athc config path` leaves the help (rule 13: rule details belong in the docs; SCHEDULER-COMMANDS.txt keeps it), since the two folders a Commissioner must find are the game's, not the config folder.
20. **No check or preview mode.** The rule validator is test code and a coach has no schedule to check that is not already the game's; the Commissioner reads the report. Adding a mode would be a feature without a workflow.

## 5. The command

Click 8.4.1's own rendering at its 78 columns, with `-h` from athc's `CONTEXT_SETTINGS`, in cli-help.md's style (the epilog prints verbatim; its second line is 77 columns with its indent):

```
Usage: athc generate-schedule [OPTIONS]

  Generate a league's season schedule and report.

  Reads the league's .lge file from --previous (the previous season:
  standings) and --upcoming (the upcoming season: conferences, divisions, team
  names; default: path in league.toml), then writes a .txt and .html schedule
  plus an .html report to the current folder, named schedule_YEAR_DATE_TIME.

Options:
  --season YEAR       Season to schedule, e.g. 2048.  [required]
  --previous FOLDER   Folder holding the previous season's league files, saved
                      after its last playoff game.  [required]
  --upcoming FOLDER   Folder holding the upcoming season's league files
                      (default: path in league.toml).
  --seed NUMBER       Seed for a repeatable run (default: random; the last
                      line shows it).
  --time-limit LIMIT  Solver budget for placing games into weeks, in the
                      solver's own time units, not seconds (default:
                      time_limit in scheduler.toml).
  --league NAME       League to use (default: the one set with athc config set
                      league).
  -h, --help          Show this message and exit.

  Examples:

    athc generate-schedule --season 2050 --previous "E:\PNFL\2049 final"
    athc generate-schedule --season 2030 --league PCFL --previous D:\PCFL\2029
```

```

athc generate-schedule --season 2030 --league PCFL --previous D:\PCFL\2029 --upcoming D:\PCFL\2030
```

### Inputs

| Input | Where | Needed | What is missing or wrong |
|---|---|---|---|
| the previous season's `.lge` | `--previous FOLDER`, as `<FOLDER>\<league>.lge` | yes | absent folder or file: Windows' phrase naming the file; broken: the lge library's line; unfinished: `Season not finished: <n> game(s) not played.`; a team with no upcoming match: `Team(s) not in <upcoming>: ... List renamed teams under [renames.YEAR] in <scheduler.toml>.` |
| the upcoming season's `.lge` | `--upcoming FOLDER`, else `path` in `league.toml`, else the "No path" line | yes | as above for absent or broken; a team with no previous match: `Team(s) not in <previous>: ...`; not two conferences of nine: the structure error naming it |
| `scheduler.toml` | the league folder | no, every key defaults | bad TOML or a bad value: `FAIL <file>: ...`, as today; a bad `[renames.YEAR]` entry: its line naming the table and key; `time_limit` or `phase1_time_limit` at 0 or below: the positive-number line (decision 11) |
| `league.toml`, `path` | the league folder | unless `--upcoming` | `FAIL <league.toml>: No path for the league. Set path in this file, or pass --upcoming.` |
| `athc.ini`, `[athc] league` | the config folder | unless `--league` | `FAIL No league selected. Run 'athc config set league NAME' or pass --league. Available: ...`, as today |

- **The two folders:** `--previous` is always given; `--upcoming` follows the path rule (absent: `path`; `.`: the current folder; a folder: that folder). The same folder for both is the `WARN` of decision 7, before anything is read.
- **Order of output:** the `WARN`, if any, then nothing until the two files and `scheduler.toml` are read and the folder check passes; then the progress lines on stderr in the order the solve runs (`Generating the <season> schedule`, `Phase 1: ...`, `Phase 2: ...`), then the three `OK   <file>` lines on stdout in the order written (`.txt`, `.html`, `_report.html`), then `Generated <n> games (seed <s>)`. An error stops the run at its line; nothing is written before the solve ends.
- **Output folder:** the current folder; the three names share one minute stamp, and a file of the same name is replaced.
- **Ctrl+C:** anywhere in the run, `FAIL Interrupted.`, 130, nothing written; during a solve the search stops at the press (decision 16).
- **Argument errors:** Click's, exit 2: a missing `--season` or `--previous`, `--upcoming` without a value (`Option '--upcoming' requires an argument.`), a value that is not an integer, a seed outside 0 to 2147483647, a time limit under 1, an unknown option (`No such option '--workers'.`).
